# 动态配置静态前缀导航

## 问题与行为

`config("huawei.game_list.{$gameid}.appid")` 在 0.1.3 中整个表达式不参与导航。优化后，点击 `huawei` 打开 `config/huawei.php`，点击 `game_list` 定位该文件中的键名；`{$gameid}` 和后面的 `appid` 不推断具体游戏配置。

仅补齐双引号插值字符串中首个动态部分之前、以点号结束的完整静态路径段。普通完整静态配置键继续沿用 0.1.3 的最终键跳转行为。半截键名、转义后无法直接对应源码偏移的片段、动态段后缀和 heredoc 不猜测目标。动态字符串拼接暂不扩展。

## 实施与验证

1. 在 `test/config.test.cjs` 补充静态前缀分段跳转及无错误跳转用例，先复现失败。
2. 在 `visitConfigCalls` 中复用现有 `configTarget`，依据 PHP AST 字符串片段建立精确路径段范围，不修改全局静态求值规则。
3. 验证真实调用、Cursor / VS Code 宿主的 F12 位置和动态后缀无配置跳转。
4. 更新版本 0.1.4，构建、回归及打包后通过既有 GitHub Release 方式发布，不覆盖旧版。

## 验证记录

- 实现前静态前缀跳转用例失败；实现后构建及类型检查通过，38 项自动化测试通过，完成只读代码复核。
- 真实业务项目 `ReportEvent.php` 中的表达式已只读验证：文件段打开 `config/huawei.php`，`game_list` 定位该文件第 8 行，动态段和后缀没有配置目标。
- 最终代码的 VS Code 隔离宿主验收通过，覆盖动态前缀 F12 的文件与键名位置、动态边界，以及既有 API / Facade / 静态配置导航和编辑失效场景。
- 首轮同时启动的宿主提前退出且没有输出具体断言；改为串行后 VS Code 通过。随后 Cursor 可执行文件路径不存在（ENOENT），本次不将 Cursor 宿主标记为通过；未修改应用安装。临时诊断代码已移除。
