# 相对请求地址导航

## 问题与原因

API 使用 `const URL_PREFIX = 'admin'`，请求地址为 `URL_PREFIX + '/user-data-query/get-blacklist'` 时无法跳转。

前端解析已经得到 `admin/user-data-query/get-blacklist`，但索引的路径规范化仅接受 `/` 开头的地址，导致路由匹配前被过滤。这是插件限制，不需要修改业务项目的 API 写法。

## 修复

本地相对地址与 `/` 开头的地址统一拼接配置的 `requestBasePath`。默认 `/api` 下，上述地址匹配 `/api/admin/user-data-query/get-blacklist`。继续排除协议地址与 `//` 开头的外部地址，不删除或猜测业务前缀。

## 验证方式

- 回归用例覆盖 const 拼接、斜杠开头地址、URL 形式基础路径，以及外部地址排除；修复前相对地址用例失败。
- 执行类型检查、构建及完整自动化测试。
- 使用实际测试项目源码只读构建索引，检查 `getBlacklist` 请求位置能否定位到控制器方法。
- VSIX 更新后需在 VS Code 重新加载扩展；静态索引验证不等同于实际鼠标交互验收。
