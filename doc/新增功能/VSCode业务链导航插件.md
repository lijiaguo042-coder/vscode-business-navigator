# VS Code 业务链导航插件

## 功能与实现

独立扩展以本仓库根目录为入口，开发工具、测试和说明集中维护，不修改被导航应用的业务代码或数据库。

- Cmd+点击 / F12：接口 URL 到控制器方法、路由 handler 到控制器、可确定的 Resource / 服务方法调用。
- 业务链侧栏：页面、API、路由、控制器与直接服务方法的上下游关联，源码点击、循环停止展开、当前入口固定。
- 反向引用：从后端方法经路由和 API 收集 Vue 等实际调用位置。
- 纯静态：Babel、Vue 2 script 提取、php-parser 共用关联索引；不运行 PHP / Artisan、不读取 `.env`、不发业务请求。
- 按工作区独立维护快照；后台 Worker 解析；编辑防抖、磁盘事件失效、关闭丢弃刷新、嵌套父工作区同步失效。

配置与安装入口见插件目录 `README.md`，配置项统一使用 `businessNavigator` 前缀；默认请求基础路径 `/api`，可按项目覆盖。默认排除依赖、产物及插件自身，不跟随符号链接。

## 验证方式

插件目录执行 `npm run check`、`npm run build`、`npm test`、`npm run test:host`、`npm run package`。构建只作用于插件，不执行项目生产构建。VSIX 安装后，在示例 API 的 URL 上 F12，应打开对应控制器方法；侧栏保留中间路由节点。

初始集成检查已验证 API 到控制器，以及控制器到注入服务、反查 Vue 页面的关联。类型检查、独立构建和 23 项自动化测试已通过，VSIX 已成功打包。真实 Extension Development Host 已通过 URL 定义、F12 对应命令、Vue 到 API、控制器到服务、反向 Vue 引用、侧栏命令、入口固定、未保存编辑、关闭丢弃、嵌套工作区编辑及路由文件重命名验收。另在隔离扩展目录中激活本机已有 Intelephense 1.18.5 和 Vetur 0.37.3，与本插件共存的同组验收通过。

## 已知边界

导航是源码关联，不是运行时调用图。动态容器绑定、复杂控制流、继承 / Trait 方法回溯及跨函数数据流保守显示未解析；不模拟路由运行时条件、域名、正则约束或覆盖顺序。资源名仅使用常见单数化规则。

`clone($value)` 等部分合法写法可能触发解析库在 PHP 7.1 模式的限制，文件诊断不代表已确认应用代码语法错误；受影响文件暂不建立方法关联。

上述验收是程序化真实宿主测试；物理鼠标 Cmd+点击和侧栏视觉布局未完成独立人工交互验证。UI 工具当前绑定的是用户原有 Code 窗口，未操作该窗口以免影响已有会话。宿主运行时出现 VS Code 自身联网握手失败和退出 UtilityProcessWorker 日志，测试进程最终退出码为 0；这些日志不作为插件运行失败依据。
