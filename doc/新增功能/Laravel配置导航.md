# Laravel 配置导航

## 问题与设计

`config('application.upload_zipfile_v2')` 应定位到 `config/application.php` 返回数组中的 `upload_zipfile_v2` 键。原实现没有默认扫描配置目录，也没有建立配置键关联。

默认源码目录加入 `config`，复用 PHP AST 解析静态 `config()` / `\config()` 及明确导入的全局 config 函数别名。支持文件级配置名、点分嵌套键和静态字符串拼接；目标范围只包含键名，不把配置值写入标签或诊断。PHP 顶层及方法中的调用均参与导航和反向引用，侧栏沿用同一关系图。

只接受配置文件唯一顶层 return 的静态数组结构；不执行 PHP、读取 `.env` 或推测运行时覆盖。动态键、设置数组、缺失文件 / 键、同名自定义函数、被其他函数导入遮蔽的 config 保持无跳转。用户覆盖 `sourceRoots` 时需自行包含 `config`，额外排除项继续有效。

## 实施与验证步骤

1. 新增配置导航回归用例，验证当前版本失败；覆盖顶层调用、嵌套键、文件入口和不应跳转的边界。
2. 默认目录加入 `config`，PHP 分析结果增加配置引用，索引合并配置节点和调用关联，侧栏显示配置类型。
3. 验证配置扫描、未保存覆盖与排除规则；真实 Cursor 宿主验证 F12、未保存配置编辑及丢弃恢复。
4. 在只读业务项目中复验 `application.upload_zipfile_v2`，构建并打包为 0.1.3；本次不覆盖既有 0.1.2 Release。

## 验证记录

- 实现前配置导航与默认扫描用例失败；实现后构建及 TypeScript 类型检查通过，完整自动化测试 36 项通过。
- 同名命名空间函数、显式 `namespace\config`、条件 / 嵌套函数声明遮蔽的边界已加入回归，完成只读复核。
- 使用业务项目当前源码只读建索引，调用定位 `config/application.php:437` 的 `upload_zipfile_v2` 键名；未输出配置值或修改业务项目。
- Cursor 和 VS Code 隔离真实宿主的配置键 F12、精确目标范围、反向引用、未保存配置改名和丢弃恢复通过，既有 API / Facade 导航和文件变更验收同时通过。
- 首次宿主断言错误地要求 F12 选中整个键名，而编辑器实际将光标落在键名起点；已改为分别验证定义范围和光标落点。
- 程序化 F12 验收不等同于独立物理鼠标交互验收，Windows / Linux 未独立验收。
